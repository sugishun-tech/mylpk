# 対応範囲と制約事項

この版は独自LP/MILPエンジンの初期実装です。「すべての数学者が要求する機能」「あらゆるケースで最速」「GLPK/Pyomoの完全な置換」は達成・保証していません。

## 数値エンジン

入力行列は疎形式ですが、基底LUは密行列です。標準化後の行数をmとすると、主要な基底保存量はO(m²)、再分解の計算量はO(m³)です。変数の有限上限や両側制約は標準形の行を増やします。元の行数だけでメモリ使用量を判断しないでください。

固定変数の除去、定数行の確認・除去を行います。高度なbound propagation、係数縮約、dominated row/column除去など、産業用ソルバー並みのpresolveではありません。列スケーリング、疎LU、Forrest–Tomlin更新、Devex/steepest-edge pricing、ネイティブ内点法は未実装です。

MILPの探索管理、再定式化、モデルコンパイルはPythonです。数値ピボットをCythonで実装しており、全処理がCythonという構成ではありません。探索木内での並列分枝限定法、Gomory/MIRカット、強分枝、一般のユーザーカット、lazy constraint callback、厳密MILP証明ログは未実装です。カバーカットは二値行を対象とする根ノード処理に限定します。

単体法では退化が続くとBland型選択に切り替えますが、有限精度演算のため、数学的な無限精度の終了保証をそのまま主張できません。極端な係数幅、ほぼ特異な基底、巨大なBig-Mでは `numerical_error` になり得ます。係数・単位を整理し、別ソルバーで照合してください。

## 解と証明

`optimal` は設定した許容誤差内での数値的な終了状態です。`mip_abs_gap` による枝刈りを含むため、目的差がその閾値以内の点を厳密に区別するものではありません。閾値を0にしても浮動小数点演算や実行可能性の許容誤差は残ります。

`make_exact_certificate()` は浮動小数点解の有理数再構成を試し、証明条件をFractionで検査します。厳密有理数単体法ではありません。入力は**保存済みfloat64の十進文字列表現を厳密な有理数として解釈した問題**です。元の入力で既に丸められた1/3などを自動復元しません。

Farkas証拠は二段階法・双対単体法が返せる場合の標準形座標の数値証拠です。すべての実行不可能終了で証拠が得られるわけではありません。presolveによる矛盾検出ではメッセージだけの場合があります。元モデル座標へのFarkas証明変換や厳密有理数Farkas証明は未実装です。

IISは選んだソルバーの判定と許容誤差に基づく削除法です。包含関係で極小の矛盾集合を求めますが、最小要素数の集合ではありません。既定では整数性を緩和します。整数性を保った半連続・半整数モデルのIISは未対応です。

感度区間は**スケーリング済み標準形で、一つの係数だけを変え、基底を固定した場合の差分区間**です。元の変数・元の係数の区間や、複数係数を同時に変えるロバスト領域ではありません。冗長行に人工基底が残る場合は未対応です。

## モデリング

myomoはPythonの内部DSLです。Pyomo互換APIでも、独立した構文解析器を持つ外部言語でもありません。`.mod` / `.dat`、GNU MathProg、AMPLファイルの読込みはありません。

式の次数は2までです。三次以上、決定変数による除算、sin/exp/logなどの一般的な非線形式、複素最適化、SDP、SOCP、MIQP、MINLPは未対応です。QP/QCQPは明示指定したSciPy SLSQPに接続し、局所的な結果を返す補助機能です。大域最適性、凸性判定、二次双対値の提供は保証しません。

indicator、絶対値の厳密等式、二値×連続積、SOS、区分線形などは線形化・二値再定式化です。有限境界が必要です。ユーザー指定Mの**非負性**は検査しますが、Mの数学的な妥当性までは証明できません。自動Mも変数区間から導出する上界であり、制約全体を使った最小Mではありません。

`abs_epigraph` / `max_epigraph` / `min_hypograph` はそれぞれ不等式表現です。目的関数などが補助変数を適切に押さえなければ、元の関数値との等式にはなりません。

二値パターン列挙は指定した二値変数の組合せを区別します。連続変数を含む全最適解集合の列挙ではありません。辞書式最適化は各段階を別問題として解きます。これらのワークフローの返却値はスナップショットであり、一時制約を戻した元モデルの現在最適解としてキャッシュしません。

`clone()` は線形の数値スナップショットを作り、パラメータをその時点の値に固定します。記号式・遅延パラメータの構造的な複製ではありません。式辞書、MatrixBlockの行列・境界配列、内部リストを直接書き換えることはサポートしません。更新可能なParameter、変数境界・種別、Constraintの上下限、公開メソッドを使用してください。

## 速度・時間制限・並列

単体法の時間確認は最大128ピボットごとのチャンク境界です。人工変数の清掃やLU分解は途中で中断しません。`time_limit` は厳密な実時間デッドラインではありません。MILPコールバックはノード処理単位です。独立した `solve_many()` はスレッドを使いますが、GILを保持する準備処理、BLASスレッド、コピーなどの影響を受けます。常に並列化で速くなるとは限りません。

LPSessionは行列・変数境界・行の構造を固定して使います。目的係数、目的の向き・定数、有限/無限や等式/不等式の構造を変えないRHS値だけ変更できます。行列や変数境界の変更、保存したLUのディスク永続化は未対応です。

## 外部連携とファイル

GLPKとhighspy、Pyomoは検証環境に未導入です。アダプターの実装と、必要な依存が存在すれば動く条件付きテストを同梱していますが、実機検証済みとは扱いません。ブリッジ先ソルバーのインストール・設定は別途必要です。各バックエンドは同じ機能を返せるとは限りません。

JSONは本プロジェクトの線形問題スキーマです。記号モデルの再保存ではなく数値スナップショットです。MPSは自由形式の線形サブセットで、名前中の空白を持つ厳密な固定桁MPSや方言の全機能には対応しません。目的定数の符号、integer markerの既定境界、OBJSENSEの扱いは他ソルバーとの差に注意してください。[APIの入出力仕様](API.md) を参照してください。

本プロジェクトのテストは合成問題と回帰テストを中心にしています。Netlib/MIPLIB全体、長時間の大規模実務問題、クロスプラットフォーム検証は実施していません。
