# 性能測定

## 条件

同梱 `benchmarks/run.py` による2026-10-07の一環境でのマイクロベンチマークです。独自ソルバーと、SciPyを通じたHiGHSを比較しています。外部の標準ベンチマーク集全体を実行したものではありません。

CPU表示はAMD EPYC 9V74、Linux x86-64、CPython 3.13.5、Cython 3.2.4、NumPy 2.3.5、SciPy 1.17.0です。コンテナから見える論理CPUは5です。CPU名の80-Coreという表示を専有コア数と解釈しないでください。

`OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1` を指定し、threadpoolctlで検出したBLASプールは1スレッドでした。HiGHS内部のスレッド数は独立に計測していません。Cython拡張は既定のポータブルビルドで、`MYLPK_NATIVE` は使用していません。

乱数seedは20261007、各条件にウォームアップ1回、測定5回を実施し、中央値を掲載しています。コールド求解とは基底やソルバー状態を再利用しないことを指し、プロセス起動や初回モジュールimportの時間は含みません。

## 単発LP・MILP

| ケース | 元の行数×変数数 | mylpk [ms] | HiGHS経路 [ms] | 目的値照合 |
|---|---:|---:|---:|---|
| dense_20x40 | 20×40 | 1.657 | 2.598 | 一致 |
| dense_80x160 | 80×160 | 3.415 | 6.901 | 一致 |
| sparse_120x600 | 120×600 | 24.875 | 11.551 | 一致 |
| transport_12x12 | 24×144 | 2.267 | 2.323 | 一致 |
| binary_knapsack_18 | 3×18 | 16.899 | 2.942 | 一致 |

単位はミリ秒で、小さいほど短時間です。各ケースの全試行の時間、状態、目的値、反復数、ノード数、実行可能性を `reports/benchmark.json` に保存しています。

`LinearProblem` 構築後の入力を使用します。求解時の標準化、内部コピー、postsolve、返却解の検査は計測に含め、myomoの式構築は別測定としています。両ソルバーとも各求解の時間上限は10秒、相対MIPギャップは0です。アルゴリズムやpresolveの実装を一致させた実験ではありません。

密な小規模LPでは独自経路が短時間でした。一方、120×600の疎LPと18変数二値問題ではHiGHS経路が短時間でした。輸送問題のような小さな差を一般的な優劣へ拡張できません。これだけでGLPKやHiGHSより一般的に高速だと結論することはできません。

## LUを保持する反復求解

| 40行×100変数、初回＋20回の目的係数更新 | 合計時間の中央値 [ms] |
|---|---:|
| mylpk LPSession、初回を含む | 15.757 |
| mylpk、毎回新しく求解 | 44.762 |
| HiGHS経路、毎回新しく求解 | 74.444 |

初回求解を含む21回分の合計時間を、一つの試行として測っています。LPSessionは20回の更新でワークスペースを再利用し、同じ入力列について全経路の最終試行の目的値を照合しました。HiGHS側はSciPy経路で毎回新規求解しています。HiGHSのネイティブpersistent APIとの比較ではありません。

この測定では、独自コア単体の命令速度だけでなく、標準化・コピー・LU再構成を省ける効果が含まれます。

## myomoの式構築

| 変数項数 | 組込みsum [ms] | myomo.quicksum [ms] |
|---:|---:|---:|
| 1000 | 49.440 | 0.268 |
| 5000 | 1190.020 | 1.327 |

既に作成した変数の一次式を合計する時間です。変数作成、モデルコンパイル、求解は含みません。組込みsumでは、項を追加するたびに既存の係数辞書をコピーします。quicksumは一回の走査で蓄積するため、この用途では差が大きくなります。

この差は主としてアルゴリズム・データ構造の差であり、Cython化だけによる速度向上率ではありません。Pyomoのquicksumや他のモデリングライブラリとの比較ではありません。

## 再現

```bash
python -m pip install '.[dev]'
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
  python benchmarks/run.py --repeats 5 --output reports/benchmark.json
```

生成するケースはコードに固定され、測定後に有利なケースだけを選ぶ処理はありません。失敗・制限到達・目的値不一致もJSONに記録し、検証できなかった場合には終了時にエラーを出します。環境負荷、コンパイラ、BLAS、Python/SciPyの版、CPU命令セットにより測定値は変わります。

今後比較するべき対象は大規模疎LP、長時間MILP、標準問題集、native persistent HiGHS、Pyomoのモデル構築です。この配布物では未測定であり、数値を推測で補っていません。
